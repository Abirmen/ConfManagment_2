# Визуализация графа зависимостей Rust-пакетов (Cargo)

**Дисциплина:** Конфигурационное управление  
**Вариант:** № 2  
**Язык реализации:** Python 3  
**Формат конфигурации:** XML

## Описание проекта

Консольное приложение для анализа зависимостей пакетов Rust (Cargo) и визуализации полученного графа. Программа настраивается через XML-файл. Реализация ведётся последовательно в пять этапов.

> **Важно:** готовые менеджеры пакетов и библиотеки для получения зависимостей не используются. Информация о зависимостях извлекается собственной логикой программы с использованием стандартных модулей Python (`xml.etree.ElementTree`, `urllib.request`, `json`).

**Текущий статус:** реализованы этапы 1 и 2 (чтение/валидация XML-конфигурации и извлечение прямых зависимостей заданной версии Cargo-пакета по HTTP). Разделы про этапы 3–5 описывают планируемую функциональность.

## Этап 1. Минимальный прототип с конфигурацией

**Цель:** разработать минимальное CLI-приложение, читающее параметры из XML-конфигурации.

Параметры:

| Параметр | Назначение |
| --- | --- |
| `package_name` | Имя анализируемого пакета |
| `repository` | URL-адрес репозитория или путь к файлу тестового репозитория |
| `test_mode` | Включение режима тестового репозитория |
| `package_version` | Версия пакета |
| `output_file` | Имя выходного файла с изображением графа |
| `ascii_tree` | Включение ASCII-дерева зависимостей |
| `filter_substring` | Подстрока для исключения пакетов из анализа |

### Пример `config.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<config>
    <package_name>serde_derive</package_name>
    <repository>https://crates.io</repository>
    <test_mode>false</test_mode>
    <package_version>1.0.210</package_version>
    <output_file>graph.svg</output_file>
    <ascii_tree>true</ascii_tree>
    <filter_substring>dev</filter_substring>
</config>
```

## Этап 2. Сбор данных

**Цель:** получить прямые зависимости заданной версии Rust-пакета (Cargo) по URL репозитория без вызова `cargo` и сторонних библиотек.

Реализованная логика (`src/cargo_repo.py`):

1. Считываются `package_name`, `package_version` и `repository` из проверенного XML.
2. Поддерживаются два протокола Cargo-репозиториев:
   - HTTP API реестра (`https://crates.io` — эндпоинт `/api/v1/crates/<name>/<version>/dependencies`);
   - Sparse-индекс Cargo (`https://index.crates.io` — построчный JSON индексного файла пакета).
3. Из метаданных отбираются обязательные прямые зависимости секции `[dependencies]` (`kind = "normal"`, `optional = false`), устраняются дубликаты и выполняется сортировка по имени.
4. Прямые зависимости заданной версии пакета выводятся на экран.

### Коды ошибок приложения

| Код | Причина |
| --- | --- |
| `E01` | Файл конфигурации не найден или не читается |
| `E02` | Некорректный XML |
| `E03` | Отсутствующий параметр или некорректная структура XML |
| `E04` | Неверное имя пакета |
| `E05` | Неверное булево значение (`test_mode`, `ascii_tree`) |
| `E06` | Некорректный URL или путь к тестовому файлу |
| `E07` | Неверный формат версии |
| `E08` | Неверное имя выходного SVG-файла |
| `E09` | Недопустимое значение фильтра |
| `E10` | Дублирование параметра в XML |
| `E11` | Пакет или заданная версия не найдены в репозитории Cargo |
| `E12` | Сетевая ошибка или ошибка HTTP при обращении к репозиторию |
| `E13` | Некорректный формат метаданных ответа репозитория |
| `E14` | Запуск `test_mode=true` до реализации тестового графа на этапе 3 |

## Этап 3. Основные операции (план)

- Построение транзитивного графа зависимостей **DFS без рекурсии** (явный стек).
- Исключение пакетов, имена которых содержат `filter_substring`.
- Корректная обработка циклических зависимостей.
- Поддержка тестового режима из файла с именами пакетов из заглавных латинских букв.

## Этап 4. Дополнительные операции (план)

- Вывод порядка загрузки зависимостей для заданного пакета.
- Демонстрация на тестовом репозитории и сравнение с `cargo` с объяснением расхождений.

## Этап 5. Визуализация (план)

- Генерация представления графа на языке диаграмм **D2** и сохранение **SVG** в `output_file`.
- Вывод ASCII-дерева при `ascii_tree=true`.
- Демонстрация на трёх пакетах и сравнение со штатными средствами Cargo.

## Запуск

Требуется Python 3.9 или новее, сторонние пакеты не используются.

Пакет с прямыми зависимостями (`serde_derive 1.0.210`):

```bash
python src/main.py --config config.xml
```

Пример вывода этапа 2:

```text
Прямые зависимости serde_derive 1.0.210:
- proc-macro2 (^1.0.74)
- quote (^1.0.35)
- syn (^2.0.56)
```

Пакет без обязательных прямых зависимостей (`itoa 1.0.11`):

```bash
python src/main.py --config examples/config-no-deps.xml
```

Пример вывода:

```text
Прямые зависимости itoa 1.0.11: отсутствуют
```
