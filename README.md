# Визуализация графа зависимостей Rust-пакетов (Cargo)

**Дисциплина:** Конфигурационное управление  
**Вариант:** № 2  
**Язык реализации:** Python 3  
**Интерфейс:** параметры командной строки (файл конфигурации не требуется)

## Описание проекта

Консольное приложение для сбора, анализа и визуализации графа зависимостей пакетов Rust (Cargo). Все параметры передаются аргументами командной строки — отдельный `config.xml` программе не нужен. Все пять этапов задания полностью реализованы без использования готовых менеджеров пакетов (`cargo`) и сторонних библиотек разрешения зависимостей — задействованы исключительно модули стандартной библиотеки Python (`urllib.request`, `json`, `html`, `subprocess`).

## Параметры командной строки

| Флаг | По умолчанию | Назначение |
| --- | --- | --- |
| `-p`, `--package` | `serde_derive` (в тестовом режиме — `A`) | Имя анализируемого пакета (`A-Z` при `--test-mode`) |
| `-r`, `--repository` | `https://crates.io` (в тестовом режиме — `examples/test-repository.txt`) | URL репозитория Cargo или путь к файлу тестового графа |
| `--test-mode` | выключен | Режим работы с файлом тестового репозитория |
| `--version` | последняя стабильная (в тестовом режиме — `1.0.0`) | Анализируемая версия пакета в формате SemVer |
| `-o`, `--output` | `graph.svg` (в тестовом режиме — `test-graph.svg`) | Имя выходного SVG-файла с изображением графа |
| `--ascii-tree` / `--no-ascii-tree` | включено | Вывод зависимостей в консоль в формате ASCII-дерева |
| `--filter` | пусто | Подстрока для исключения пакетов из анализа |
| `--show-graph` | выключен | Дополнительно вывести список смежности графа |
| `--load-order` | выключен | Дополнительно вывести порядок загрузки зависимостей |

Запуск вообще без аргументов строит граф последней стабильной версии `serde_derive` из `https://crates.io` и сохраняет его в `graph.svg`.

## Архитектура и реализованные этапы

### Этап 1. Минимальный прототип с параметрами командной строки (`src/main.py`)

Разбор и строгая валидация девяти параметров CLI:

* имя пакета проверяется по стандарту имён Cargo, в тестовом режиме допускаются только заглавные латинские буквы (`A-Z`);
* источник в обычном режиме проверяется как URL со схемой `http://` или `https://`, в тестовом режиме — как существующий файл;
* версия должна соответствовать формату семантического версионирования `X.Y.Z` (возможны суффиксы), а при отсутствии флага выбирается последняя стабильная версия пакета;
* имя выходного файла обязано заканчиваться на `.svg`;
* подстрока фильтрации не должна содержать управляющих символов.

### Этап 2. Сбор данных (`src/cargo_repo.py`)

Получение метаданных по HTTP напрямую из реестра Cargo (`https://crates.io` API и sparse-индекс `https://index.crates.io`), фильтрация обязательных зависимостей времени выполнения (`kind = "normal"`, `optional = false`) и собственная реализация разрешения SemVer-диапазонов (`^`, `~`, `>=`, `<=`, `=`, `*`). Если версия корневого пакета не задана, выбирается его последняя стабильная версия.

### Этап 3. Основные операции (`src/dep_graph.py`)

Построение полного транзитивного графа зависимостей алгоритмом **DFS без рекурсии** (на явном стеке с трёхцветной разметкой состояний вершин), исключение узлов по `--filter`, обнаружение циклических зависимостей (включая самозависимости) и поддержка локальных тестовых графов с пакетами `A-Z`.

### Этап 4. Дополнительные операции (`src/load_order.py`)

Расчёт порядка загрузки зависимостей волновым алгоритмом Кана (обратная топологическая сортировка от листьев к корню) с отдельной обработкой циклических графов и приближённым порядком после разрыва обратных рёбер DFS (доступен через флаг `--load-order`).

### Этап 5. Визуализация (`src/visualizer.py`, `src/svg_renderer.py`)

1. Формирование текстового описания графа на языке диаграмм **D2** (`direction: down`, стилизация корня и пунктирная разметка обратных рёбер циклов).
2. Экспорт графа в файл формата **SVG** (`--output`): автоматически используется установленный бинарник `d2` (если найден в `PATH`), либо встроенный послойный SVG-рендерер на стандартной библиотеке Python.
3. **Версии пакетов отображаются прямо на изображении:** в каждом узле под именем пакета подписывается выбранная версия (`v1.2.3`), а в D2-описании — `имя (1.2.3)`.
4. Нерекурсивное построение и вывод **ASCII-дерева** зависимостей при включённом `--ascii-tree` с отметкой повторно встречающихся поддеревьев `(*)` и циклов `[цикл]`.

## Версии пакетов в изображениях

* В обычном режиме для каждого пакета разрешается конкретная версия по SemVer-требованию, и она подписывается в узле графа (в SVG — второй строкой, в D2 — в скобках после имени).
* В тестовом режиме версии задаются прямо в файле тестового репозитория: `A@1.0.0: B@1.2.0, C@2.0.1`. Формат `@версия` необязателен и поддерживается как для пакета, так и для его зависимостей.

## Коды ошибок приложения

| Код | Причина |
| --- | --- |
| `E04` | Недопустимое имя пакета (или не `A-Z` в тестовом режиме) |
| `E06` | Некорректный URL или не найден файл тестового репозитория |
| `E07` | Неверный формат версии SemVer |
| `E08` | Некорректное имя выходного файла (требуется `*.svg`) |
| `E09` | Недопустимые управляющие символы в `--filter` |
| `E11` | Пакет или подходящая версия отсутствуют в источнике |
| `E12` | Сетевая ошибка или ошибка HTTP при запросе к репозиторию |
| `E13` | Повреждённый формат JSON-метаданных репозитория |
| `E15` | Синтаксическая ошибка в файле тестового репозитория |
| `E16` | Ошибка записи выходного SVG-файла на диск |

## Примеры визуализации для трёх различных пакетов Cargo (Этап 5)

### Пример 1. Пакет `serde_derive` (`1.0.210`) — граф процедурных макросов

Запуск (сохраняет изображение `graph.svg`):

```bash
python src/main.py --package serde_derive --version 1.0.210 --output graph.svg --filter dev
```

Сформированное представление D2:

```d2
direction: down

"serde_derive": "serde_derive (1.0.210)" {style.fill: "#dbeafe"}
"proc-macro2": "proc-macro2 (1.0.106)"
"quote": "quote (1.0.45)"
"syn": "syn (1.0.109 / 2.0.x)"
"unicode-ident": "unicode-ident (1.0.24)"

"serde_derive" -> "proc-macro2"
"serde_derive" -> "quote"
"serde_derive" -> "syn"
"proc-macro2" -> "unicode-ident"
"quote" -> "proc-macro2"
"syn" -> "proc-macro2"
"syn" -> "unicode-ident"
```

Вывод ASCII-дерева (`--ascii-tree`):

```text
serde_derive v1.0.210
├── proc-macro2 v1.0.106
│   └── unicode-ident v1.0.24
├── quote v1.0.45
│   └── proc-macro2 v1.0.106 (*)
└── syn v2.0.117
    ├── proc-macro2 v1.0.106 (*)
    └── unicode-ident v1.0.24
```

## Сравнение со штатными инструментами визуализации Cargo

Штатным средством визуализации структуры зависимостей в менеджере пакетов Rust выступает команда **`cargo tree`** (а для машиночитаемой выгрузки графа — `cargo metadata --format-version 1`; встроенной генерации D2 или SVG в базовой поставке `cargo` нет).

Сопоставление результатов на трёх рассмотренных пакетах:

1. **`http 1.1.0` — полное совпадение:** как `cargo tree -e normal`, так и наш инструмент строят идентичное дерево из трёх листьев (`bytes`, `fnv`, `itoa`).
2. **`serde_derive 1.0.210` — различие в одном опциональном ребре:** в `cargo tree` у пакета `syn` дополнительно отображается ребро `syn -> quote`, тогда как в нашем выводе у `syn` присутствуют только `proc-macro2` и `unicode-ident`. В `Cargo.toml` пакета `syn` зависимость `quote` объявлена с флагом `optional = true` и активируется через `default`-фичу `printing`.
3. **`url 2.5.0` — различие при передаче фич вниз по дереву:** в `cargo tree` под пакетом `tinyvec` появляется узел `tinyvec_macros`, поскольку `unicode-normalization` запрашивает `tinyvec` с фичей `alloc`, включающей опциональную зависимость `tinyvec_macros`.

Обобщённые причины возможных расхождений между нашим анализатором и `cargo` / `cargo tree`:

- **Объединение фич (`features` и `default-features`):** `cargo` вычисляет транзитивное замыкание активированных фич и подключает связанные с ними `optional = true` зависимости; наш инструмент без интерпретатора фич учитывает строго обязательные зависимости (`optional = false`).
- **Сборочные и тестовые зависимости (`build` / `dev`):** `cargo tree` по умолчанию включает `[build-dependencies]` (скрипты `build.rs`, например `cc`, `autocfg`), тогда как наш инструмент анализирует исключительно зависимости времени выполнения (`kind = "normal"`).
- **Целевая платформа (`cfg(...)` / `--target`):** `cargo` отфильтровывает платформенные ветви под текущую ОС и архитектуру, а в сырых метаданных реестра все такие записи имеют `kind = "normal"`.
- **Глобальное разрешение версий и `Cargo.lock`:** `cargo` решает систему ограничений глобально и допускает сосуществование разных SemVer-несовместимых мажорных версий одного пакета в одном графе, тогда как наш итеративный обход выбирает наибольшую подходящую версию при первом обращении.

## Запуск и дополнительные режимы

Стандартный запуск без аргументов (последняя версия `serde_derive`, SVG и ASCII-дерево):

```bash
python src/main.py
```

Явное указание пакета и версии:

```bash
python src/main.py --package http --version 1.1.0 --output http-graph.svg
```

Тестовый режим с локальным графом (версии пакетов берутся из файла репозитория):

```bash
python src/main.py --test-mode
python src/main.py --test-mode --repository examples/test-cycle-repository.txt --show-graph --load-order
```

Дополнительный вывод списка смежности (этап 3) и порядка загрузки (этап 4):

```bash
python src/main.py --test-mode --show-graph --load-order
python src/main.py --package url --version 2.5.0 --show-graph --load-order
```
