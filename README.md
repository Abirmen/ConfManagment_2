# Визуализация графа зависимостей Rust-пакетов (Cargo)

**Дисциплина:** Конфигурационное управление  
**Вариант:** № 2  
**Язык реализации:** Python 3  
**Формат конфигурации:** XML

## Описание проекта

Консольное приложение для анализа зависимостей пакетов Rust (Cargo) и визуализации полученного графа. Программа настраивается через XML-файл. Реализация ведётся последовательно в пять этапов.

> **Важно:** готовые менеджеры пакетов и библиотеки для получения зависимостей не используются. Информация о зависимостях должна извлекаться собственной логикой программы. Допускается использование стандартных модулей Python для чтения XML, обработки JSON, HTTP-запросов и работы с файлами, если преподаватель не установил дополнительных ограничений.

**Текущий статус:** реализован этап 1 (чтение и проверка конфигурации). Разделы про этапы 2–5 описывают требования и планируемую функциональность; они не означают, что эти возможности уже реализованы.

## Этап 1. Минимальный прототип с конфигурацией

**Цель:** разработать минимальное CLI-приложение, читающее параметры из XML-конфигурации.

Параметры:

| Параметр | Назначение |
| --- | --- |
| `package_name` | Имя анализируемого пакета |
| `repository` | URL-адрес репозитория или путь к файлу тестового репозитория |
| `test_mode` | Включение режима тестового репозитория |
| `package_version` | Версия пакета |
| `output_file` | Имя выходного файла с изображением графа |
| `ascii_tree` | Включение ASCII-дерева зависимостей |
| `filter_substring` | Подстрока для исключения пакетов из анализа |

При запуске программа проверяет конфигурацию и выводит все семь значений в формате `ключ: значение`. Для каждого параметра предусмотрена обработка ошибочного ввода.

### Пример `config.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<config>
    <package_name>serde</package_name>
    <repository>https://crates.io</repository>
    <test_mode>false</test_mode>
    <package_version>1.0.210</package_version>
    <output_file>graph.svg</output_file>
    <ascii_tree>true</ascii_tree>
    <filter_substring>dev</filter_substring>
</config>
```

### Обработка ошибок в текущем прототипе

| Код | Причина |
| --- | --- |
| `E01` | Файл конфигурации не найден или не читается |
| `E02` | Некорректный XML |
| `E03` | Отсутствующий параметр или некорректная структура XML |
| `E04` | Неверное имя пакета |
| `E05` | Неверное булево значение (`test_mode`, `ascii_tree`) |
| `E06` | Некорректный URL или путь к тестовому файлу |
| `E07` | Неверный формат версии |
| `E08` | Неверное имя выходного SVG-файла |
| `E09` | Недопустимое значение фильтра |
| `E10` | Дублирование параметра в XML |

При успешной проверке приложение возвращает код `0`, при ошибке конфигурации — `1`.

## Этап 2. Сбор данных

**Цель:** получить прямые зависимости заданного Rust-пакета.

Планируемые операции:

1. Считать имя пакета, конкретную версию и URL репозитория из XML.
2. Самостоятельно запросить метаданные пакета в репозитории формата Cargo.
3. Извлечь прямые зависимости именно заданной версии пакета.
4. Вывести найденные прямые зависимости в консоль.

Получение зависимостей нельзя делегировать `cargo tree`, `cargo metadata` или готовым библиотекам для анализа зависимостей.

## Этап 3. Основные операции

**Цель:** построить граф прямых и транзитивных зависимостей.

Требования:

- Использовать **DFS без рекурсии** (явный стек).
- Исключать из анализа пакеты, имена которых содержат `filter_substring`.
- Корректно обрабатывать циклы, не допуская бесконечного обхода.
- Поддерживать тестовый режим: вместо реального URL считывать описание графа из файла; названия пакетов в тестовом графе — заглавные латинские буквы.
- Демонстрировать работу на нескольких графах, включая граф с циклом, разветвлениями и фильтрацией.

Пример условного **тестового** файла (формат строк выбирается в реализации, поскольку заданием он не зафиксирован):

```text
A: B, C
B: C
C:
```

## Этап 4. Дополнительные операции

**Цель:** вывести порядок загрузки зависимостей заданного пакета.

Планируется вычислять порядок по построенному графу с учётом зависимостей между узлами, демонстрировать результат на нескольких тестовых графах и сравнивать его с результатом реального менеджера пакетов Cargo. При обнаружении расхождений необходимо объяснять их причины. Порядок для циклического графа требует отдельной обработки: обычный топологический порядок для графа с циклом не существует.

## Этап 5. Визуализация

**Цель:** получить текстовую и графическую визуализацию зависимостей.

Требования:

1. Сформировать описание графа на языке диаграмм **D2**.
2. Сохранить изображение графа в формате **SVG** с именем из `output_file`.
3. Если `ascii_tree=true`, выводить зависимости в виде ASCII-дерева.
4. Продемонстрировать визуализации для трёх различных пакетов.
5. Сравнить результаты со штатными средствами визуализации менеджера Cargo и объяснить возможные отличия.

Для построения SVG на этом этапе потребуется реализовать или подключить механизм рендеринга D2. При этом запрет задания на **готовые средства получения зависимостей** сохраняется.

## Запуск

Требуется Python 3.9 или новее. Для первого этапа сторонние библиотеки не нужны.

Из корня проекта:

```bash
python src/main.py --config config.xml
```

Пример запуска с тестовым файлом:

```bash
python src/main.py --config examples/config-test.xml
```

Windows:

```bat
run.bat
```

Linux/macOS:

```bash
sh run.sh
```

### Пример вывода первого этапа

```text
package_name: serde
repository: https://crates.io
test_mode: false
package_version: 1.0.210
output_file: graph.svg
ascii_tree: true
filter_substring: dev
```

> На первом этапе файл `graph.svg` не создаётся: `output_file` только читается и проверяется.

### Что демонстрировать на защите

**Этап 1:** корректный XML, вывод всех семи параметров, несуществующий файл, сломанный XML, пропущенные и повторяющиеся элементы, некорректные значения каждого параметра; режим тестового файла.

**Этап 2 (после реализации):** получение прямых зависимостей для конкретной версии Cargo-пакета; пакет без зависимостей, отсутствующий пакет, неизвестная версия и ошибки сети.

**Этап 3 (после реализации):** цепочка зависимостей, ветвление, общий зависимый пакет, цикл, изолированная вершина, исключение по подстроке и чтение тестового графа из файла.

**Этап 4 (после реализации):** порядок загрузки в простом и разветвлённом графах; обработка циклов; сопоставление с Cargo и объяснение различий.

**Этап 5 (после реализации):** D2-описание графа, корректно сформированный SVG, переключение ASCII-режима и примеры для трёх пакетов.

## Работа с Git

Каждый этап нужно фиксировать отдельными информативными коммитами в публичном репозитории. Использовать стиль **Conventional/Scoped Commits**. Например:

```bash
git add README.md .gitignore config.xml src tests examples run.sh run.bat
git commit -m "feat(config): implement XML configuration for stage 1"
```

Для последующих этапов можно использовать сообщения:

```text
feat(deps): collect direct Cargo dependencies
feat(graph): build dependency graph using iterative DFS
feat(order): calculate dependency loading order
feat(viz): generate D2 representation and SVG output
```

В репозиторий не следует добавлять ZIP-архивы, бинарные файлы, `__pycache__`, файлы редактора и прочие генерируемые артефакты. Код должен соответствовать ограничениям из задания, включая длину строк Python (не более 80 символов), длину функций (не более 40 строк), число аргументов (не более 7), docstring вместо комментариев-документации, разумную цикломатическую сложность и имена по PEP 8.
